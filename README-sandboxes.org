#+TITLE: Browser and server-backed sandboxes
#+OPTIONS: ^:nil toc:2

Build prerequisites are in [[file:README-build.org][README-build.org]]. These interfaces share contracts and household
policy code; they serve different purposes from the five-year acceptance campaign.

The browser-only wallet sandbox now deploys corrected =Buck= with compounded
cash, per-facility liabilities, the external Jubilee fund and the same four
libraries used by Python. Its real identity proofs, premium reserve, market
transactions and save/restore are tested. Wallets show net cash and BUCK
liabilities separately; each insurer owns its own certified Carrying premium
pool. Buys account for the pool's carried fees and report actual net delivery.
Default trades require a positive output bound within 1% of the current spot
estimate, before execution; larger price impact can therefore refuse a trade.

Both machine deployment/bootstrap paths now reuse canonical Buck's linked
basket and Jubilee fund, with real pool pairing and premium-bearing issuance.
Their basket is an approved Carrying service: balanceOf/transfers are nominal,
while portfolio marks, reserves, collateral and redemption minimums are net.
The shared market helper grosses up cash payouts and records actual values.
Funded wheel ROI and carried-fee exchange are described in the
[[file:doc/BASKET-WHEEL.org::*Implemented Carrying-basket path (2026-11-08)][wheel implementation note]].
=make nix-core-equilibrium-bootstrap-test= tests that stage through the demo
artifact bundle. =make nix-venv-economy-bootstrap-test= adds the existing
Python builder, bootstrap agents, desk and component comparisons.
=make nix-venv-economy-accounting-test= also validates exact Python/JS receipt
marks and a short Python loop through JSON/PDF reporting. Both complete
household lifecycles still await conversion. Full economy save/restore is a
later task and does not gate uninterrupted interactive or five-year runs.
The primary worlds also expose the existing guarded market and exact USDC
payment helpers through their ordinary proxies. The [[file:README-households.org][household refinancing machine]]
can apply a funded plan's confirmed bank principal/costs and recover interrupted
phases once. The dated calendar now authenticates wages, bills and mortgage
payments; automatic economic decisions/savings/exits remain gated.
Its exact event stream is already retained by both server frame modes
for a future individual/aggregate status view.
Existing debtor/saver/investor account and facility setup now works in both
languages, with matching SDK credit books and personal portfolio records.
These records include all custody cash/TOKENs, actual NFT debt, each insurer
pool's refund mark and exact receipt basis/mark/ROI, without changing the
underlying cash-flow history. Explicit refinance and calendar operations are
tested; the normal automatic dispatcher remains gated. The
[[file:doc/review/bucknet-economy-implementation.org][unified Buck accounting plan]] records that boundary. Wallet success is not
five-year household evidence. The cash-only basket in the wallet world is not
bound to the K controller; a working household savings lifecycle remains a
separate gate from the tested public basket onboarding and contract lifecycles.

The common JavaScript constructor is
=buildBuckWorld(session, artifacts, {identity, accounting: "net"})=. It now
uses =Buck=, rather than the BuckNet facade, with a separate Jubilee fund and
operator-bound simulation insurer pool. =SimLP= is the transparent simulation
pool account; its unrestricted =exec= is not an insurer investment strategy.
=make nix-venv-net-demurrage-smoke= tests the shared Python/Anvil and JS/Tevm
stack, including guarded V3 trading in both token orders. The single-pool guard
checks net output separately from sponsor compensation; it is not a price
oracle or multi-hop router.

Wallet save format 4 contains net-world ABI version 7, the on-chain model
identifier, library addresses, code hashes and verified fund/market/pool
wiring. Incompatible imports are rejected. Browser storage uses a separate
entry for this model; the old signed-accounting entry is retained rather than
converted or overwritten. Saved hashes check record consistency, not external
release provenance. The separate cash-only receipt-mark tests currently use
an explicit identity harness; they do not establish production basket binding.

* Browser-only wallet sandbox

#+begin_src sh
make nix-sandbox SANDBOX_PORT=8980
#+end_src

Open =http://127.0.0.1:8980/=. This builds =core/js/sandbox/dist/= and serves it. The EVM runs
inside the tab. It is not a five-year economy; a page with no simulation server does not show
the Savings tab. Its browser test exercises identity, payment, credit and reload behavior.
Use the documented acceptance target to build and run the Node controller and
real Chromium page together; it owns its temporary static server:

#+begin_src sh
make nix-wallet-sandbox-test
#+end_src

* Savings sandbox (accounting migration pending)

This page uses a Python economy behind JavaScript controls and wallet views.
The server and page can start, but normal household stepping still reaches
the explicit issuance/exit migration gate. Its end-to-end savings acceptance
is not yet restored. =make nix-venv-economy-accounting-test= checks the
available role setup, portfolio, market and short reporting components;
=make nix-wallet-sandbox-test= checks the runnable browser-only wallet.

The household-position selector shows each arrived household's remaining open basket basis,
its current BUCK share mark and marked ROI. The return is the mark divided by remaining basis
less one, before exit costs; it excludes closed receipts. The aggregate chart shows the same
open basis and marks for households together. The personal savings receipts also show their
on-chain BUCK basis and share mark. A pro-rata receipt without an equity share mark is shown
as unavailable rather than assigned an invented return.

#+begin_src sh
make nix-venv-sim-savings SIM_SAVINGS_PORT=8981
#+end_src

Open =http://127.0.0.1:8981/=. One server serves both the page and its Python worlds, with a
separate world for each session. Controls create worlds with explicit household policies and
population settings. Existing sessions retain their chosen settings. The default model is
the same household economy used by the five-year runner; the dormant shock actor enables
interactive stress buttons without adding a standing stabilizer. Opening counts and arrival rates
are controlled separately for mortgage debtors, insured savers and cash investors. The Make
target adds =--set scenario.agents.ShockAgent=1= to the common =economy.toml= preset.

For a previously built deployment, =sim-savings-serve= starts only the server. Building and
starting are separate operations; updating source files does not reload a running process.
The server is not started, stopped or redeployed by a test or report target unless that target
explicitly says it owns a temporary server. Choose unused ports for local work.
When a server-backed world completes five years, it saves a uniquely named
JSON and adjacent PDF under =build/sim/completed/= and logs their paths; an
interrupted world may leave an incomplete checkpoint. See [[file:README-simulations.org][the simulations guide]]
for report recovery and interpretation.

#+begin_src sh
make nix-venv-sandbox-savings-test SAVINGS_TEST_PORT=8987
#+end_src

This is the full savings acceptance target to restore after the household
decision migration; a successful page build alone does not pass it.
It owns its temporary server and stops that process afterwards. Nix supplies the Chromium
matching =playwright-core=. =make nix-core-test-js= also runs available browser tests; it
reports a skip when an external savings page is not supplied. See the test output rather
than treating a skipped browser test as coverage.

* JavaScript equilibrium demo (accounting migration pending)

The canonical deployment/bootstrap check is available now:

#+begin_src sh
make nix-core-equilibrium-bootstrap-test
#+end_src

It creates the opening weighted pools and checks actual premium-bearing
issuance, personal portfolios and guarded proxy-market transactions. The
commands below build the existing interface, whose household
execution remains gated while its cash/debt operations are migrated.

#+begin_src sh
make nix-core-demo-eqworld-serve EQWORLD_PORT=8983
#+end_src

Open =http://127.0.0.1:8983/eqworld.html=. Its credit household and saver use the same policy
kernel as Python, with real contract execution through Tevm. This small world is useful for
interaction and model conformance; its charts do not substitute for the population grid.

The older identity/buckworld pages are focused protocol demonstrations. Their broader tour is
in [[file:doc/SANDBOX.org][doc/SANDBOX.org]]. Deployment and hosting remain in the deployment book; local build/test
commands do not publish a site or update a hosted service.

The same small household loop also has a command-line demonstration:

#+begin_src sh
make nix-core-eqsim JS_EQ_ARGS='--days 14 --policy adaptive'
#+end_src

It writes =build/sim/js-eqsim.svg= (K, BVIB, price and household net worth) and
=build/sim/js-eqsim.jsonl= (the operation journal). This is useful for contract/agent diagnosis;
the Python campaign supplies five-year acceptance. The CLI's =--payment= means monthly net
household income, with the mortgage payment calculated from its terms. =--policy= replaces
the old prototype's =--aggr= knob. Its default mortgage is half the insured asset value.
