#+TITLE: On-Chain Groth16 Verifier Export Bug
#+SUBTITLE: Root Cause: Non-Deterministic snarkjs groth16 setup
#+author: Perry Kundert
#+date: 2026-06-05
#+description: snarkjs groth16 setup (g16s) is non-deterministic — produces different delta values per run.  The zkey, proof, and exported Solidity verifier must always be regenerated together.

* Symptom

Freshly exported Solidity Groth16 verifiers fail on-chain with
=PrecompileError= on the =bn256Pairing= precompile (EIP-197).  The
off-chain =snarkjs groth16 verify= passes.  Old verifiers generated
before the nixpkgs upgrade continue to work.

The failing gas value is the sentinel =0xF800000000000000000000000000000017=
(~1.78e19) — a forge-internal error code for precompile failure.

* Eliminated Causes

| Cause                      | Tested                                   | Result |
|----------------------------+------------------------------------------+--------|
| circom version             | 2.2.2 (old nixpkgs) vs 2.2.3 (26.05)    | Both fail for fresh verifiers |
| snarkjs version            | 0.7.5 vs 0.7.6                           | Both fail |
| forge version              | 1.5.1 (old nixpkgs) vs 1.7.1 (26.05)    | Both fail |
| solc version               | 0.8.28 (old nixpkgs) vs 0.8.33 (26.05)   | Both fail |
| npm transitive deps        | Locked, integrity hashes match           | Eliminated |
| ptau files                 | Unchanged, deterministic                 | Eliminated |
| field element bounds       | All values < r                           | Eliminated |
| circuit complexity         | Flat identity_membership (no circom-lib) | Still fails |
| historical pipeline        | Exact script from commit 7d2f686        | Still fails |

* Root Cause: Non-Deterministic =groth16 setup=

The =snarkjs groth16 setup= (aka =g16s=) step is *non-deterministic*.
Running the same R1CS + ptau twice produces different delta constants
in the zkey:

#+begin_example
Run 1: deltax1 = 5167194652017777113745952798103111761868745835054487248983325220486810944626
Run 2: deltax1 = 16376280843904757355699941505129212791775630624088232096536638690402677703224
#+end_example

The IC, alpha, beta, and gamma constants are stable (from the ptau).
Only delta varies (from zkey setup randomness).

* Consequence

The zkey, proof, and exported Solidity verifier are a *matched set*.
If any of them is regenerated, all three must be regenerated together.
Partial rebuilds produce mismatched artifacts:
- A new zkey ⇒ new proof needed
- A new zkey ⇒ new verifier constants (delta) needed
- A recompiled circuit ⇒ new R1CS ⇒ new zkey needed

* Fix

1. The =make snark-g1tie= (and all =make snark-*=) targets must
   *always* clean the build directory before rebuilding, ensuring
   all artifacts come from the same =groth16 setup= run.
2. The setup script must be run atomically — never manually run
   individual steps out of order.
3. The exported Solidity verifier and test vectors must be committed
   together, never separately.

* Historical Note

The working =IdentityMembershipVerifier.sol= (commit =7d2f686=) was
generated by a single =scripts/snark/setup_identity_membership.sh=
invocation that ran all steps in sequence.  The verifier, proof, and
vectors were a matched set.  When we later tried to regenerate just
the verifier (or just the proof), the non-determinism produced
mismatched deltas.

* Reproduction Commands

Always use =make snark-g1tie= (which cleans + rebuilds atomically):

#+begin_src bash
make snark-g1tie-clean   # drops build/snark/g1tie
make snark-g1tie         # full atomic rebuild: compile -> setup -> prove -> export
#+end_src

The setup script (=scripts/snark/setup_g1tie.sh=) runs:
  1. circom compile
  2. groth16 setup (non-deterministic)
  3. zkey contribute (deterministic with fixed entropy)
  4. prove + off-chain verify
  5. export Solidity verifier
  6. generate Forge test vectors

All steps use the same zkey from step 2.
