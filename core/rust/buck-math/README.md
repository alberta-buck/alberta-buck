# alberta-buck-math

Integer monetary arithmetic for the Alberta Buck system: depreciation,
demurrage, the on-chain PID controller, and full-width `mulDiv`.

The Solidity contracts are the specification.  Every function here is
bit-identical to the deployed-code paths -- not approximately, exactly --
and that claim is proven rather than asserted: `tests/vectors/math-vectors.json`
is generated by forge from the contracts themselves, and this crate's test
suite replays every row.  The Python and JavaScript builds of the same kernel
replay the same file.

Rules of the crate: integer math only, no floats ever; `no_std` and
dependency-free, so a Holochain zome can take it; floor division everywhere;
and overflow panics in exactly the places Solidity 0.8 checked arithmetic
reverts, in every profile.

## Install

```toml
[dependencies]
alberta-buck-math = "0.1"
```

The distribution is prefixed, the import is not:

```rust
use buck_math::{fee_owing, SECONDS_PER_YEAR};
```

## Example

Demurrage on an idle balance -- one BUCK (1e6 raw units) held for a year
owes 2%:

```rust
use buck_math::{fee_owing, SECONDS_PER_YEAR};

let fee = fee_owing(0, 1_000_000, SECONDS_PER_YEAR as u64);
// 19_999 -- the per-second rate floors 2e25 / 31_557_600, as the contract does
```

The modules mirror the contracts they specify: `depreciation` (BuckCredit
`_depreciate` / `currentValue`), `demurrage` (Buck `_feeOwing` /
`_carryingTransfer`), `pid` (BuckKControllerDirect's rescaled-ppm PID,
funding factor and bumpless retune algebra), and `wide` (OpenZeppelin
`Math.mulDiv` semantics).
