#+TITLE: Simulations: running, reading and reducing them
#+OPTIONS: ^:nil toc:2

Use [[file:README-build.org][the build guide]] first. =make help= lists the supported paths. The canonical economic model
is =alberta_buck/sim/experiments/economy.toml=; its household policies are implemented in both
Python and JavaScript. The Python engine is used for five-year evidence, JavaScript for browser
interaction and cross-language contract tests. They are not independent economic hypotheses.

* What each suite detects

| Suite | Question | Entry point | Result |
|-------+----------+-------------+--------|
| Household economy | Can households, K and the basket machine balance supply and liquidity demand? | =economy-plan/run/report= | JSON, adjacent PDF, campaign HTML and summary JSON |
| Household policy/contract tests | Do both languages make the same decisions and move real funds correctly? | =economy-test= | pytest and Node test results |
| Routing and contract tests | Do swaps, identities, accounting, guards and interfaces work? | =test-python=, =test= | Test failures and targeted vectors |
| Control lab | Which feedback component causes a response or instability? | =control-lab-plan/interactive/verify= | Cached traces and an offline interactive page |
| Sandboxes | Can a person operate a wallet, credit line and savings account? | See [[file:README-sandboxes.org][sandboxes]] | Interactive state and exported data |

Keep these distinct checks. A five-year parity average cannot detect a broken wallet workflow;
a short diagnostic trace cannot establish an economic equilibrium.

* The household default

=adaptive= saves through BUCK deposits, reducing new purchases as the BUCK becomes expensive.
At a basket-relative discount after costs it retires liabilities with increasing urgency,
using suitable basket receipts and then spare cash. It retains the cash and BUCK funding needed
for a worthwhile issuance before discretionary saving. Credit savers can borrow at a premium;
mortgage borrowers refinance when reduced carrying cost justifies execution and switching costs.
Working balances, asset sales and arrival behavior are shared across policy comparisons.

The comparison settings are =basket= (always invest spare cash, no discretionary paydown),
=retire= (retire liabilities regardless of parity) and =discount= (retire below the individual
discount threshold, otherwise retain cash). Asset-sale settlement still clears liabilities in
every policy. The exact sampled settings and arrival roster are recorded in each vector.

*Naming changed on 2026-10-25.* On the household-economy branch before this date, =basket=
already included price-sensitive saving and discounted paydown. That behavior is now called
=adaptive=. Earlier =adaptive= was a different premium/discount-band policy. Interpret saved
runs using their frozen source commit, not today's label. The older four-policy funding
campaign held parity on all policies and cleared every mortgage; it did not establish a
universally best policy. The newer default is the agreed behavioral baseline, not a promise
that every population mix passes.

* Inspect, smoke-test, run

#+begin_src sh
make nix-venv-economy-plan CELLS=centre
make nix-venv-economy-smoke ECONOMY_SMOKE_DAYS=30
# Commit the source changes before starting a long campaign.
make nix-venv-economy-run CAMPAIGN=baseline CELLS=centre JOBS=2
make nix-venv-economy-run CAMPAIGN=baseline CELLS=grid JOBS=4
make nix-venv-economy-run CAMPAIGN=policy-check CELLS=policies JOBS=4
make nix-venv-economy-plan CELLS=stress
make nix-venv-economy-run CAMPAIGN=stress-check CELLS=stress JOBS=4
make nix-venv-economy-report CAMPAIGN=baseline
#+end_src

=economy-smoke= uses the working tree and writes =build/sim/economy-smoke.{json,pdf}=.
=ECONOMY_SMOKE_OUT= changes the destination. It verifies integration, not five-year acceptance.
=ECONOMY_DAYS= shortens a campaign for infrastructure checks; give it a distinct campaign name.
=ECONOMY_SEED= selects a seed (or the seed used by =centre=). =JOBS= limits concurrent EVMs.
Commands run in the foreground; use a terminal multiplexer for long campaigns. Policy comparisons
reuse the adaptive centre cell names, so extending the same campaign to the grid skips those
already completed worlds. Use one runner per named campaign: extend it after its current run ends. =economy-report= may
read the completed results while the remaining workers run.

| CELLS | Runs | Coverage |
|-------+------+----------|
| =centre= | 2 | Both price paths at the centre, seed 41404 unless selected |
| =probe= | 6 | Centre on both seeds and paths, plus two imbalanced corners |
| =policies= | 16 | Four policies, both paths and seeds, same centre population settings |
| =grid= | 36 | Three supply rates x three adoption paces x two paths x two seeds |
| =all= | 42 | Grid plus open-loop arrivals and rising/falling growth comparisons |
| =stress= | 32 | Eight disturbances, two strengths, both seeds on the history centre |
| =paydown= | 8 | Discounted paydown enabled/disabled at the centre and selected corners |

Supply scales debtor and saver arrival rates by 1/3, 1 or 3. Demand currently scales the pace
of adopting BUCK working balances: adoption takes three years, one year or four months. It
does *not* change eventual demand once adoption completes. This limits what the grid can say
about persistent demand differences; a balance-size axis is a separate proposed experiment.
History uses the recorded price path; revert uses the reverting path. Read =economy-plan= for
the actual overrides, rather than inferring parameters from a campaign's chosen name.

Stress arms apply one change on day 730: buy/sell pressure ($0.5M/$2M over 30 days), an energy
price fall (20%/50%), a mortgage-rate increase (2/4 percentage points), lower income for the
present cohort (25%/50% for 180 days), fewer arrivals (half/none), more arrivals (1.5x/3x), or
25%/75% of current investors exiting. These use the same baseline and reporting pipeline.
They are explicit diagnostics; adding an arm does not establish five-year coverage until it
has run and its relevant failure checks have been assessed. The raid, LP-exit and book-loading
actors still need equivalent arms. =all= means the baseline grid and its growth controls;
it intentionally does not add every diagnostic or policy comparison.

* Files, completion and acceptance

Each campaign lives in =build/sim/economy/NAME/=:

- =snapshot/= is the committed tree plus needed contracts, generated inputs and native kernels.
  =source-manifest.json= records its commit and content hashes. Resuming a named campaign uses
  that snapshot, even if the checkout has changed. Use a new name for a new model.
- =runs/CELL.log= is the worker log; =CELL.partial= is a checkpoint, not a final result.
  A successful worker produces =CELL.json= and a PDF tied to its SHA256 digest. =run-settings.json= fixes the horizon; a smoke campaign
  cannot silently become a five-year campaign under the same name.
- =status.json= records worker outcomes. A nonzero process exit fails the command, even if the
  vector was written. Missing or stale PDFs can be rebuilt from JSON without another EVM run.
- =index.html= links PDFs and JSON; =summary.json= contains the numerical acceptance results.
  Open the index directly in a browser. =economy-report= rebuilds it from completed data.

Five-year acceptance uses days 365--1826: mean absolute BVIB error below 1%, 99th-percentile
error below 5%, K at least 0.05 inside its limits on 95% of days, and no continuous rail visit
longer than 30 days. Household errors anywhere in the recorded run and unfunded exits fail.
Short or incomplete daily series cannot pass. A completed economic failure is valid evidence;
investigate it rather than changing thresholds to make it green.

BVIB is the basket's price in BUCKs: above one means the BUCK is cheap, below one dear. K is
credit availability, not an interest rate. Distinguish insured face, activated limit, spendable
headroom, outstanding liability and actual issuance. Basket shares are marked assets, not
guaranteed exit proceeds. Actual and counterfactual mortgage books use the same initial cash,
income and spending assumptions. Population telemetry distinguishes scheduled, arrived and
exited members; an arrival is not automatically an issuer.

The latest pre-consolidation grid (=release=, commit =d73f047=) passed 27 of 36 cells. All held
parity within the stated average and tail tolerances; nine low-supply cells failed K's interior
requirement. Those failures remain findings. Policy renaming alone does not resolve them.

* Diagnostics and deliberate retirement

#+begin_src sh
make nix-venv-control-lab-plan
make nix-venv-control-lab-interactive CONTROL_LAB_JOBS=4
make nix-venv-control-lab-verify
make nix-venv-control-lab-interactive-render
#+end_src

The control lab preserves component isolation, guards, response timing and phase effects that
an economic grid averages away. Its generated page is under =doc/control-lab/interactive/=.
The single-run vector viewer remains useful for inspecting individual accounts and trades;
PDFs are the portable campaign record. Avoid running all diagnostic tuning sweeps routinely.

The agreed simplification is coverage-based:

| Candidate | Replacement/check required before removal | Status |
|-----------+-------------------------------------------+--------|
| Old surplus naming and one-off October policy ablations | Explicit common policy settings and shared vectors | Replaced by the policy comparison cells |
| JS mortgage prototype and standalone income actor | Shared household books plus the real equilibrium-loop test | Removed; loop, CLI and memory benchmark use CreditHouseholdAgent |
| Separate savings-sandbox preset | Common economy with a dormant interactive shock actor | Removed; server and campaign load economy.toml |
| Standalone old/new savings runner | Machine-only routine campaigns; focused basket/contract tests | Retired; historical scripts and results remain in git |
| Old mature/equilibrium/retiree presets | Household baseline and corresponding stress cases | Superseded as the routine baseline; distinct stress cases still need matching coverage |
| Synthetic credit borrowers and older debtor decisions | Household cost, gate, reuse and mortgage tests | Current households inherit only shared account helpers; legacy consumers remain pending stress coverage |
| Catalogue attack actors | Named household-economy stress arms exercising each attack | Retain actors until the corresponding arms are tested |
| Control lab components | Component isolation and guard coverage | Retain; this is different detection capability |

The detailed decisions and historical results remain in
[[file:doc/review/household-economy-plan.org][the household-economy ledger]]. Legacy files are not another recommended baseline. Retirement
must remove their callers, tests that only restate obsolete behavior, Make entries and stale
documentation together; git history remains available without keeping every replay command.
