#+TITLE: Consolidation: one test command, one simulation layout, retired contracts
#+DATE: 2026-11-14

# The owner's direction (2026-11-14): gather every simulation and test into one
# organized structure, removing duplicates; make the Makefile simple enough that
# one obvious command runs the full spectrum of tests after any change to the
# BUCK ecosystem; identify the Solidity contracts that are now obsolete and begin
# retiring them before the merge to master and the next release (PyPI, npm,
# crates.io). Built from a read-only inventory of the Makefile (2,270 lines),
# 117 forge, 102 Python and 52 JS test files, 65 experiment files and every
# contract under src/.

* Where things stand

- *No single test command.* The full spectrum today is about a dozen targets,
  overlapping: =nix-test= (all 117 forge suites, legacy included),
  =nix-venv-test-python= (all 91 Python files; it builds nothing first),
  =nix-venv-core-test= (core Python, every JS file, Rust; the browser and bundle
  tests skip themselves unless built), =core-net-math-test=,
  =economy-accounting-test=, =economy-test=, =net-demurrage-smoke=,
  =dashboard-test= (its files also run in two other targets),
  =wallet-sandbox-test=, =sandbox-savings-test=, and the packaging checks
  (=contracts-dist-check=, =third-party-notices-check=, =stage-uniswap-check=,
  =fmt-check=).
- *About half the Makefile is legacy simulation:* the pro-rata and ops basket
  modes, the rebalancing-eq matrix, the sweeps and their judges, the catalogue
  grid, the K-design steps, the TUI, the pair-observer prototype, the routing
  scenario, and four grid runners where one (=alberta_buck.sim.economy=) is
  current. Several recipes are duplicates (=sim-plot= / =plot-routing= /
  routing image; =sim-run-basket-off= / =sim-run-ops-off=); one is dead
  (=v2-patch-init-code-hash=: lib/v2-periphery is gone).
- *One simulation layout already exists and is current:* a world is a TOML
  experiment under =alberta_buck/sim/experiments/=, run by =python -m
  alberta_buck.sim= (or a grid of them by =alberta_buck.sim.economy=), recorded
  as a run record under =build/runs/= and read by one dashboard. 2 of the 65
  experiment files are current (=economy.toml=, =economy-lifecycle.toml=); about
  60 are legacy presets. The JS world is =core/js/bin/eqsim.mjs= (its run record
  is plan step R4).

* The target layout

- *Tests stay in their languages' places* (=test/= forge, =alberta_buck/test/=
  and =core/python/tests/= pytest, =core/js/test/= node): that is where each
  toolchain finds them. What changes is that every test belongs to one tier and
  every legacy one is retired or ported.
- *Simulations live in one place*: experiments in
  =alberta_buck/sim/experiments/= (current worlds only, plus the stress arms
  still to be ported), one runner, one grid, one record format, one dashboard.
  Five-year suites run on datasim.local from a worktree (a suite script per
  campaign under its =build/=).
- *Three test tiers, one name each* (the rest of the Makefile is build,
  documents, releases and simulations, grouped under their own headings):

| tier | runs | when | about |
|------+------+------+-------|
| =make nix-test= (renamed from the forge-only target, which becomes =nix-test-contracts=) | the canonical forge suites; Python and JS unit tests (no EVM) | every change | minutes |
| =make nix-test-all= | everything below, in order, stopping at the first failure: contracts (forge, all current suites); kernels and vectors (Rust, vector checks); Python (=core/python=, =alberta_buck/test=, after =sim-build= and =core-build-py=); JS (unit and webevm worlds, after the bundles it needs); browser (net-math, wallet sandbox, savings sandbox); packaging (=contracts-dist-check=, notices, Uniswap staging, =fmt-check=); worlds (the 30-day economy and lifecycle worlds, the 30-day JS world) | before a commit that changes behaviour; before a merge | an hour on webevm (the JS world tests took 66 minutes on Tevm) |
| =make nix-test-worlds= | the five-year suites (=economy=, the lifecycle mixes), here or on datasim | before a release; for research | hours |
