* Decisions (author, 2026-09-24)

1. *Remove the in-note issuer pair* =(sigma_R, sigma_s)= from B1 and A1 note identity hashes.
   It had no message and no verifier, and the batch Schnorr already authenticates the issuing
   account for every exact commitment (doc/review/privacy-paper-plan.org, findings).
2. *Domain-tag the note hashes* (v2 convention: a leading field tag, =field_tag(tag) =
   keccak(tag) mod F_R=, as the accumulator leaves already do):

   | hash            | new                                              | was                          |
   |-----------------+--------------------------------------------------+------------------------------|
   | commitment      | =Poseidon6(T_CM, flavor, v, rho, idHash, pred)=  | =Poseidon5=, untagged        |
   | spent marker    | =Poseidon3(T_NF, rho, idHash)=                   | =Poseidon3(rho, idHash, 4242)= |
   | B1 identity     | =Poseidon2(T_ID, m_issuer)=                      | + sigma pair                 |
   | A1 identity     | =Poseidon6(T_ID, eNote(4), m_issuer)=            | + sigma pair                 |
   | A2 identity     | =Poseidon11(T_ID, eNote(4), eIss(4), T(2))=      | =Poseidon10=, untagged       |

   Tags: =AlbertaBuck/Notes/Commitment/v2=, =AlbertaBuck/Notes/Nullifier/v2=,
   =AlbertaBuck/Notes/IdHash/v2=.  One identity tag serves all flavours: their arities differ.
3. *Code-only*: delete the reserved 4243 A-tag nullifier; delete dead circuits and contracts
   (=test_g=, =test_nb_minimal=, =test_pow= circuits; =TestVerifier.sol=; the single-note
   =mint.circom= + =MintGroth16Verifier.sol= + =prove_mint.js=, superseded by the batch mints).
   =setup.sh='s legacy section keeps only spend, under =DO_SPEND= (was =DO_LEGACY=);
   =prove_spend.js= takes a mint-fixture path (it defaulted to the legacy mint's).
4. *Kept*: =predicate= (reserved spend-condition slot; keeps the commitment layout stable for
   future conditions), the G1-tie circuit (review evidence), the regression verifier.
5. Finish with a fresh venv and every paper re-rendered (author's request).

* Constraints

- =vectors.py='s rng stream is pinned by the a2b section (=NotesA2Tie='s =tie= fixture):
  removed draws are RESERVED (consumed, ignored), never deleted.
- SNARK artifacts are a matched set (doc/snark-regeneration.org): regenerate every affected
  circuit, run =make nix-test= before committing, commit the whole result together.
- Python wallet functions dispatch to the Rust kernel: Python, Rust (buck-identity,
  buck-wallet, bindings) and JS change together, then the kernels rebuild.

* Notes (in flight)
