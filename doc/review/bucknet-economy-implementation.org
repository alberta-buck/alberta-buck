Commit independently tested milestones and keep the progress table current.
Do not use this worktree's experiments as evidence for production deployment.

The user chose nominal Carrying services, an adaptive household default and
explicit policy comparisons. Preserve the low-K exit guard. Keep legacy =Buck=
and its simulations until the new paths demonstrate equivalent economic and
failure detection; then retire only code whose distinct coverage is replaced.
The cash-only net basket can support early integration diagnostics but cannot
stand in for the existing leveraged basket without resolving the
[[file:basket-jubilee-crossholding.org][cross-holding valuation and liquidity problem]].

* Ordered milestones

- [ ] Provide reusable Python and browser-safe JavaScript deployment and
  operation primitives for linked =BuckNet=, its independent verified fund,
  dynamic K, per-insurer Carrying pools, issuance quotes and selected-NFT
  authorized reductions. Exercise real contract state and ordinary versus
  Carrying amounts, nonzero premiums, reserve refusal and refund behavior.
- [ ] Wire these primitives into the existing Python and JavaScript household
  agents, maintaining shared adaptive/comparison decisions, randomized
  arrivals and thresholds, real swaps, spending buffers, explicit paydown,
  and individual savings basis/mark/ROI. Do not equate a purchase with debt
  retirement or rely on a synthetic signed balance.
- [X] Exercise the existing adaptive household's discount buyback on real
  BuckNet/V3 fixtures in both languages, enforcing a net-output floor and
  counting actual selected-NFT settlements. Keep the remaining net lifecycle
  paths explicitly disabled until their own integration is complete.
- [ ] Implement automatic handling of pending and expired reduction
  authorizations, reconciling uncertain transaction outcomes before retrying
  or canceling and preserving already-acquired BUCK and settlement counters.
  Reconcile uncertain purchases as well. Persist the pending transaction and
  buyback reserve through snapshots, and decide how an unfinished buyback is
  invested or held when the market subsequently turns to a premium.
- [ ] Revisit the adaptive policy's heterogeneity: decision phases and many
  parameters are randomized, but its paydown starts at any positive discount
  and does not use the sampled =retire_disc=. If adding a personal deadband,
  prevent the earlier borrow/paydown overlap described in the household plan,
  keep Python and JS behavior identical, and document the changed policy
  before comparing fresh simulations with historical runs.
- [ ] Integrate fund and insurer keepers, maturity batches, liquidity caps,
  actual proceeds, refusal/retry telemetry and safe snapshots; support the
  existing routed markets and household accounting in both runtimes.
- [ ] Resolve and verify leveraged basket credit and fund cross-holdings,
  preserving exit and solvency guards; test repricing, dilution, self-holding,
  zero liquidity, shocks and insurer/fund callbacks. The cash-only model must
  be labeled distinctly while this remains open.
- [ ] Extend artifact bundles, local linking, core bindings, Notes receipts,
  proof statements/migration and the neutral-service allowlist as specified
  in the companion interface plan. Test real proof paths against =BuckNet=.
- [ ] Run a short new-model smoke and shared actual-EVM operation vectors on
  Python and JavaScript, then frozen five-year baseline, policy and stress
  campaigns. Every completed run needs reproducible JSON and an adjacent PDF;
  report rendering failures and preserve data. Record contract provenance.
- [ ] Compare the retained old stress, routing, credit and low-K detections;
  retire legacy agents or contracts only after their distinct checks pass in
  the replacement. Record tests, remaining fork/security/production gates
  and the precise proposed merge scope.
