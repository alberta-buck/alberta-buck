Resume document for =feature/public=: make the repository public with a front door a newcomer
can read, and a sandbox they can use in minutes.  Decisions, phases, status.

* Goal (author, 2026-09-25)

- A compelling, accessible =README.org=; setup and installation in sub-documents.
- A simulated environment that comes up quickly and is driven from a browser: issue and register
  identities, insure simulated assets and create credit, create wallets, transact BUCK.
- An asciinema demo of setting it up and running it.

* What exists (survey, 2026-09-25)

- *Browser world, no server.*  =core/js/src/buckworld.js= deploys a world into Tevm in the tab:
  =buildBuckWorld=, =onboard= (PS credential -> presentation -> ElGamal -> =registrationProve= ->
  =register=), =identityApprove= (the Chaum-Pedersen handshake), =createCredit= (credit issuer ->
  =createCredit= -> =Buck.mint=), =fundAccount=, =advanceTime=.  It deploys only =IdentityRegistry=,
  =BuckCredit=, =BuckKControllerDirect= and =Buck=, all in the published =alberta-buck-contracts=
  bundle; the web wasm kernels are in the published =alberta-buck-kernel=.  So a sandbox can be
  built from npm packages alone -- Node, no Rust, Foundry, Nix or Python.
- *Demos.*  =core/js/demo/buckworld.html= (citizens, "+1000 credit line", handshake, pay, clock,
  market) and =eqworld.html= are scripted exhibitions, not tools: no forms, no persistence.
  =identity-proofs.html= is broken (=const registry= declared twice since d0ed54d).
- *Kernels in the browser.*  =identity-web.js:loadIdentity= wraps the identity wasm (PS, ElGamal,
  registration, Chaum-Pedersen, Schnorr, notes).  =wallet-core.js:wrapWallet= (receipts, Notes
  deliveries, credential issuance, registry/regulator) has only a Node loader; the web wasm already
  exports every =wallet_*= and =registry_*= function.
- *Shared world.*  =alberta_buck/sim/server.py= serves per-session pyrevm worlds with agents:
  WebSocket =frames/control/rpc= (8797) and HTTP JSON-RPC (8798); =anvilSession= can drive it.
  No web client; no address discovery, =eth_getLogs= or time control; pyrevm lacks macOS wheels
  past cp312.
- *Not wired anywhere yet:* the insurer gate (=configureInsurerGate=, =attestInsurer=), asset
  classes, premiums and depreciation in any UI; wallets with persistence; receipts in a browser;
  Notes in a browser (proving keys are GB-scale; Python fixtures only).

* Proposal: the Alberta Buck sandbox

One static web app, =sandbox/= (Vite), running a private world in the visitor's own tab.  Built
from the published npm packages, so =npm install && npm run dev= is the whole install, and the
same build deploys to GitHub Pages as "try it in your browser" once the repository is public.
Everything is labelled SIMULATED; keys live in the browser and are for play.

Four tools, one per role in the system, over a shared world bar:

| tool          | role      | does                                                                |
|---------------+-----------+---------------------------------------------------------------------|
| World bar     | everyone  | day and clock (+1 day, +30 days), BUCK_K, reset, export/import      |
| Issuer        | registry  | a KYC form -> core record; issue a PS credential (a card to hand    |
|               |           | over); revoke; the issuer trusted on the chain                      |
| Wallet        | citizen   | create (Ethereum key + identity key, kept in the browser); import a |
|               |           | credential; register; balances, credit limit, demurrage owing; send |
|               |           | BUCK (handshake + transfer); receipts (AB-RCPT/2)                   |
| Credit        | insurer   | insure a simulated asset (class, value, depreciation, premium) -> a |
|               |           | BuckCredit NFT and credit line; the holder mints BUCK; the NFTs at  |
|               |           | their depreciated value                                             |
| Observer      | anyone    | the chain as the public sees it: decoded transactions and events -- |
|               |           | the privacy story made visible                                      |

Wallets are separate browser identities of one world, so a visitor plays issuer, insurer and two
citizens side by side.  v1 keeps the world in one page (the four tools are tabs of it); sharing it
across browser tabs needs a =SharedWorker= to hold the chain, and comes later.  The implementation
plan is =doc/review/sandbox-plan.org=.

*Later, not in v1:* a "connect to a shared world" switch pointing the same UI at the sim server
(needs address discovery, =eth_getLogs= and a time op on the server), so agents supply an economy
around the visitor; Notes (A1/A2/B1) from pre-generated fixture proofs; the insurer gate.

* The front door

=README.org= rewritten for a newcomer:

1. What Alberta Buck is, in a paragraph: money issued against insured real assets and held steady
   against a commodity basket; private by default, accountable by law.
2. *Try it*: the sandbox (hosted link; =make sandbox= locally) and the demo recording.
3. What is here: contracts, the kernels (Rust, Python, JavaScript), the simulations, the papers;
   the published packages with their registries.
4. Read: the papers in a reading order, with their PDFs.
5. Status and safety: unaudited prototype; the Groth16 setup is a development one until v1.0.0;
   =SECURITY.md=.
6. Licences and contributing, in two lines each, linking =LICENSING.md= and =CONTRIBUTING.md=.

Sub-documents under =doc/= (beside the review documents, not a second =docs/=): =INSTALL.org=
(packages from the registries; nix; the venv), =SANDBOX.org= (the web tools; written in S5),
=DEVELOP.org= (build, test, SNARK setups -- the present README's material, moved and
corrected).  =alberta-buck-deployment.org= stays the release book.
