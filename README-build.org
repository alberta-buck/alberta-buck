#+TITLE: Building and testing Alberta Buck
#+OPTIONS: ^:nil toc:2

Start with =make help=. It prints the supported entry points and runs nothing. The root
[[file:Makefile][Makefile]] is the executable command reference. [[file:README.org][README.org]] introduces the project;
[[file:README-simulations.org][simulations]] and [[file:README-sandboxes.org][sandboxes]] explain the two execution engines and their results.

* The environment wrappers

| Command | Environment |
|---------+-------------|
| =make TARGET= | The current shell; its tools and Python must already be installed |
| =make nix-TARGET= | The toolchain pinned by =flake.lock=: Foundry, Node, Rust, Python, Chromium |
| =make venv-TARGET= | This checkout's editable Python packages, in =.venv= |
| =make nix-venv-TARGET= | Both; use this for Python simulations and their tests |

=nix-= does not install JavaScript dependencies on shell entry. =make nix-js-deps= installs
the root and =core/js= packages from their lockfiles. Nothing here starts a production service.

=venv-= is non-interactive and preserves Make variables. =make nix-venv= opens an interactive
shell when wanted; =source .venv/bin/activate= activates it in an existing shell. Override
=VENV=/absolute/path= to choose another environment. Each worktree gets its own default venv.
The wrapper checks its interpreter and project metadata every time, updating packages only
when needed. If Nix garbage collection removed the interpreter, it repairs the environment in
place. It neither deletes an existing environment nor modifies the user's shell startup files.

* First checkout

Install Nix with flakes enabled, clone the repository, then:

#+begin_src sh
make nix-install                 # pinned Solidity libraries
make nix-js-deps                 # root and core/js npm dependencies
make nix-venv-setup              # Python reference, core, contracts, tests, plots, pyrevm, server
make nix-venv-core-build-py      # compiled Python kernels, staged into the editable core
make nix-sim-build              # Solidity and external venue artifacts
make nix-core-build-wasm        # Node kernels, used by JS tests
make nix-sandbox-build          # browser kernels, artifacts and page bundle
#+end_src

Python's three local distributions install together so an unpublished development version is
resolved from this checkout. The optional compiled kernel has its own build step above; the
base packages can also use their pure-Python implementation. A fresh dependency installation
requires network access. Existing locked Nix tools and installed dependencies can be reused.

Install =core/js/node_modules= separately in each worktree. npm links its kernel workspace to
the adjacent =core/js/kernel=; sharing the whole =node_modules= directory through a symlink
can silently load another checkout's wasm. The core JS build and test targets check that link.
If it is a symlink to another worktree, remove the symlink itself (not its target) before
running =make nix-core-js-deps= in this worktree.

For ordinary edits, rerun the affected build, not the entire first-checkout sequence. Contracts
build into =out/=; kernels into =core/python/buck_core/= and =core/js/kernel/=; browser output
into =core/js/sandbox/dist/=. These generated products are not committed.
Simulation builds and their artifact loaders expect this checkout's =out/=;
the Uniswap staging script does not follow a =FOUNDRY_OUT= override. Use a
separate worktree for an isolated simulation build rather than pointing only
Foundry at a different output directory.

* Tests

The [[file:doc/review/bucknet-economy-implementation.org][current accounting plan]] corrects the existing =Buck.sol= using the
BuckNet prototype's discoveries. =BuckNet*= tests remain donor/regression
diagnostics; =net-demurrage-smoke= checks the shared canonical clients.
=buck-accounting-test= exercises the
corrected =Buck= itself, its unsigned cash and the independent allocation
vectors. Both existing economy builders now bootstrap the new constructor,
linked libraries and fund/basket graph. A short Python economy now exercises
canonical cash/principal/receipt observations and completed JSON/PDF reporting.
Complete household lifecycles and persistent-state integration remain migration work. The wallet sandbox
now uses the corrected token and its own verified save format. Old test fixtures
explicitly importing =BuckLinear= are legacy evidence, as listed in the plan.
Shared setup lives in abstract fixtures. Desk accounting, invariants and
machine integration use [[file:test/basket/BasketDesk.t.sol][BasketDeskFixture]] instead of inheriting another
suite's executable tests. This removes 134 repeated executions while keeping
the same distinct checks; the plan records the before/after inventory.

=economy-test= builds its contracts and both native/Node kernels before exercising the agents,
runner and completed-run PDF reporting. Install the locked JavaScript dependencies with
=make nix-js-deps= first; =make nix-core-js-deps= is the core-only equivalent when the root
dependencies are already present. Nix does not install these packages automatically.
=PYTEST_FILES= selects files; =PYTEST_ARGS= supplies pytest options (default =-q=).
=JS_TEST_ARGS= is relative to =core/js/=. Browser tests need built pages and the Chromium
provided by Nix; check skipped-test reasons. The savings browser test additionally needs its
Python server: see [[file:README-sandboxes.org][the sandbox guide]]. Missing =anvil= is an environment failure, not a
passing integration test; use the =nix-= wrapper.

The canonical money kernel uses unsigned 256-bit inputs and 512-bit
multiply/divide intermediates. One full BUCK is =10^42= internal cash units
(six external decimals times =Q= =10^36=). =core-net-math-test= builds both
native and Node/web WASM bindings and requires the Chromium test to run;
missing or stale bindings fail this target. It checks the same independent
Python-integer vectors against Solidity, Rust, Python, Node and the browser,
including overflow and very old balances. Regenerate reviewed vectors with
=make core-net-math-vectors=; =core-net-math-vectors-check= verifies the
oracle output and the copy shipped with the Rust crate. This target starts
no economy and provides no five-year evidence. Existing =fee_owing= and
=carrying_transfer= helpers describe the retained legacy linear model;
new accounting uses =net_decay=, =net_fund_after= and =net_target_relief=.

=core-equilibrium-bootstrap-test= builds simulation artifacts and the Node
kernel, regenerates the demo bundle and uses that exact bundle to bootstrap
the existing machine world. It checks the single fund/basket graph, weighted
opening pools, governed wheel binding, zero-allowance keeper introduction,
real insurer acceptance, premium funding and independent principal. It does
not run the household decision loop; that lifecycle and full economy
save/restore remain explicit migration gates. Synthetic SimLP/router binding
still uses the labelled registry harness; production service authorization
is separately tested by the Solidity suites.

=economy-bootstrap-test= includes that JS test and builds the native kernel
for the Python path. It uses the existing Python deployment and bootstrap
agents, checks the single machine/fund/basket graph and separate desk, and
keeps the two older component configurations covered. The canonical machine
omits the disabled advisers and replaced component facet. Opening TOKEN
endowments model existing holdings, preserve declared weights and leave the
reference pools unchanged; ongoing investor purchases still trade normally.
Canonical wheel arbitrage is disabled pending its inventory/fee qualification;
an explicit =SIM_WHEEL_ARB=1= request fails. The Python wheel comparison is
also gated under corrected accounting; the existing Solidity wheel is used.

=economy-accounting-test= includes those bootstrap checks, exact receipt-mark
tests in Anvil/Tevm and the existing Python loop with a small bootstrap-only
population. Its three-day integration test shortens the PDF threshold locally
to test the automatic completion path; production still requires five years
for automatic PDFs. The completed JSON records monetary model, public role
and library addresses/code hashes, actual cash, NFT principal, Jubilee cash
and guarded publication, and each observed depositor's remaining basis/mark.
The PDF shows open-position mark-to-market returns even without redemptions.
Both household role setups and same-block SDK credit books are also covered,
including insurer-pool replacement and actual pending authorizations. Their
personal portfolio readers include all custody cash/TOKENs, exact receipt
basis/marks, actual NFT debt, premium-pool marks and guarded Jubilee claims;
full-width and negative values remain integer money through USD conversion.
The real tests include partial redemptions and deliberately stale local
trade shares. Normal decisions remain gated before new income or borrowing;
the interactive driver propagates an unimplemented action rather than
allowing readable books to become a false completed economy.
Both primary builders deploy real Permit2 and the matching single-pool net
guard. The existing SDK market/settlement helpers dispatch through the same
public household proxies: guarded net buys, user-paid bounded sales, separate
USDC payments and saved-receipt recovery. Tests use aged Carrying pools and
distinct payers/recipients. The JS primary adapter reuses selected-facility
repayment recovery instead of duplicating it. Sales do not implicitly retire
either mortgage or NFT principal. Complete household scheduling is still
gated. The [[file:README-households.org][household refinancing machine]] now acquires a bounded net reserve when needed and applies an assessed plan's
authenticated bank principal and costs once, including recovery after a lost
reply. Shared insurance vectors and real activation/retirement tests verify
proportional external premium costs. Explicit read-only economic assessment
now selects actual bounded candidates with observed default forecasts or
explicit comparisons. The explicit calendar now authenticates wages/bills
once and keeps dated actual/counterfactual mortgage books moving through
receipt delays. Both Python runners and the JS day clock use absolute
calendar targets and a shared household epoch, so rounding and wheel waits
cannot accumulate extra modeled bank days. Normal automatic policy/surplus/exits and restoration remain
separate gates. Tests stream exact histories through full/lite JSON
without depending on the optional compact action log.
The sim-build dependency now includes the vendored Permit2 build.
Ordinary households use one facility per asset; explicit multi-asset fixtures
retain the distinct age/pool cases. Shared full-width market-estimate vectors
run before the slower JS primary-world acceptance and in the Python phase.
Actual V3 checks compare estimates with guarded delivery and bounded exact-net
reserve acquisition; the two-token-order SDK fixture retains both directions.
This is component/reporting integration coverage, not household-policy or five-year
stability evidence. No extra economy runner is introduced.
Pytest owns =build/test/economy-accounting/=: each target run replaces that
scratch directory and leaves the latest integration =canonical.json= and
=canonical.pdf= below it for inspection. Campaign output is kept separately.

Foundry excludes SNARK tests whose generated proof fixtures are absent, visibly. Their setup
and regeneration, executable papers, release builds and deployment procedures remain in
[[file:doc/DEVELOP.org][doc/DEVELOP.org]] and [[file:alberta-buck-deployment.org][the deployment book]]. Simulations do not replace contract tests.
The deployment dry run exercises the legacy bootstrap with stub Notes verifiers. It does not
deploy the experimental =BuckNet= stack or establish readiness for a live deployment.
The corrected =Buck= links =BuckCash=, =BuckTransfer=, =BuckFacilities= and
=BuckRenewalOps= in that dependency order. Foundry links them for its tests;
the shared Python/JS deployment helper links actual creation-bytecode metadata.
Its fifth constructor argument is the external Jubilee fund; the earlier
insurance-pool argument is not reused. The helper then deploys the existing
optional quoter and configures immutable authority bindings. The legacy Notes
bootstrap does not deploy this graph. The existing basket and upkeep facets
also link =BasketJubileeMath= for valuation and =BasketMarketOps= for net cash,
market operations and funded ROI arb. No second wheel or fund is introduced.
=deploy_net_basket= / =deployNetBasket= return both helper addresses and
their fully qualified link map. Identity, venues, fund wiring
and leverage remain explicit. Saved net-world records use version 7, verify
the canonical accounting identifier and record the four token libraries plus
the basket valuation/market helper code bindings. They reject earlier deployments
and incomplete records.

The canonical one-call =burn= supports ordinary owners and approved Carrying services. It
requires the original insurer pools to have any required nominal refund and allowance
ready before the call; its bounded allocation can revert with
=AllocationWorkLimit=. The separate authorized =JubileeFund.reduce= path can
still ask an insurer pool to prepare its refund before settlement. Neither
path sells Jubilee's basket position inside the token lock.
Local contract-bundle generation now includes the
experimental net stack and its creation/runtime link metadata alongside legacy contracts;
the already published package is unchanged until a release. =make nix-contracts-dist-check=
checks compiler, bytecode links and code-size limits without publishing. The generated
browser sandbox bundle also includes the experimental artifacts; its existing interface
still runs the legacy model until its separate migration is complete.

* Useful checks

#+begin_src sh
make help
make nix-print-PYTHON_V
make print-VENV
make nix-venv-economy-plan CELLS=centre
#+end_src

These inspect the environment and plan without running an economy. For a changed model, use
=economy-smoke= before committing, then freeze the commit through =economy-run=. Do not edit
a running campaign's snapshot. The simulation guide explains why a completed process, a
completed vector and an equilibrium acceptance result are three separate checks.

* Preparing contract packages

#+begin_src sh
make nix-test
make nix-contracts-dist
make nix-contracts-dist-check
make nix-third-party-notices-check
#+end_src

These commands build and check local artifacts; they do not publish packages. The contracts use
the pinned default Foundry profile and =out/=. Emission writes the npm bundle in =core/contracts/=
and the Python copy in =core/contracts/python/buck_contracts/=.

Currently =contracts-dist-check= validates compiler and code-size constraints on built artifacts;
it does not compare already emitted package files with the build. Re-emit after contract changes,
and verify their contents/digests before publication. The [[file:doc/review/household-release-readiness.org][current release review]] records this gap,
the remaining household and shock checks, and the proposed legacy-contract retirement order.
The [[file:alberta-buck-deployment.org][deployment book]] describes package publication order and release tags.
